## 2026-11-21 证据审计补丁（策略完全冻结）

- **目的**：记录原策略可能不具备正收益优势的可复核证据，**不调整任何参数，不启用候选过滤**。旧历史回测 5 组过滤 × 4 个持有期 × 价格门槛重复检验后，筛出的最优组本身有选择偏差，**最优组不作独立结论**。
- **信号锁档**：新增 `signal-evidence.yml`。每个有实际收盘数据的交易日后，在北京时间次日 03:35 尝试把原 `data/screen.json` 的 `entry_signal=true` 记录写入独立 `signal-evidence-ledger` 分支。每份包含所属交易日、数据生成时间、首次封存 UTC/北京时间、原始 main SHA、原文件 SHA-256、信号内容 SHA-256、封存记录 SHA-256 和前一记录哈希。分支只接收**新增当日文件**；已有日期冲突失败，不回填、不覆盖；旧数据不能冒充当时已锁档的记录。**首个可验证的封存交易日不得早于 2026-11-23**。
- **强制外部保护**：GitHub 当前未配置仓库 Ruleset，且连接器无权限配置 Branch Protection。脚本与普通非 force Git push 能防意外覆盖，**但不能对抗管理员强制推送或删除**。必须在 GitHub Settings → Rules → Rulesets 为 `signal-evidence-ledger` 禁止 force push 和删除、管理员不设绕过，并在仓库外保留每日 GitHub commit SHA 才能建立更可信的审计链；即使如此也不是独立第三方 WORM 存证。**封存工作流在检测到上述规则未生效、存在绕过权限或 API 不可核验时直接失败，不会写入任何伪称不可改的档案。** 未保护前不得称“绝对不可篡改”。
- **随机对照**：`scripts/build_matched_control.js` 仅用同股同月、同历史分区、固定 SHA 种子产生非买入信号日对照。两组使用同一个原版 V2 回测执行器和 100 股、T+1、手续费、印花税、滑点、ATR 止盈止损及持有期限；不直接减去沪深300指数。报告绝对差额及**按股票代码整簇重抽样**的 95% 区间，而非把重叠的8000笔视为独立样本。历史区已被反复查看，对照**不构成独立前瞻验证**。
- **覆盖缺口**：报告依据当前股票目录展示历史有效覆盖与未覆盖、当前名称含 ST/退的数量；没有历史成分股／退市／逐日 ST 数据时将**研究期退市数及历史 ST 数标为未知**，不能伪造零值。
- **手机体验**：原始 `data/signal_tracker.json` 原样保留，不再把整个文件装进网页包；网页从 `site/data/tracker/index.json` 读取统计，从 `recent30.json` 读取最近30个日历日事件。历史按信号日期 YYYY-MM 分片、指定起止日期后按需读取，不自动加载全部旧事件。表格首列固定，显示“左右滑动看全表”。
- **评分说明**：评分只作排序，不表示符合全部入选条件；“候选股评分”和“收盘确认信号”的阈值保持原样。
- **状态措辞**：V2.2 是非自动执行的个人研究台，未启用可直接执行的券商买卖提醒。盘中研究观察标签与正式可执行预警不是一回事；行情延迟或不可用时研究提示会暂停。代码中原有的观察逻辑保持冻结。
- **不变性验收**：封存了 000001（截止 2026-11-17）真实日 K 线作回归样本；三日模拟交易数=8、胜率=25%、累计盈亏=-98.81738711178517元、PF=0.19465087708979673，升级前后必须逐项一致。回测引擎、量化公式、历史信号统计和缓存文件不在本次修改范围。
- **自动任务命名**：源码 PR 测试工作流改名为 `research-ci.yml`；实际定时盘后数据任务是 `baostock-backfill.yml`，而 `daily.yml` 仅供手动触发，不应作为正式定时任务写入操作说明。

- **一次比较 1 / 3 / 5 / 10 个交易日**，同时提供单股和所有已覆盖历史股票的池化对比。

- V2.0 第一次公开的历史样本外分界日期 **2026-07-21 冻结不再移动**。以后新增历史数据不会被重新划入“训练集”，避免将已检验过的样本外反复用于选参数。

- 本机模拟持仓显示卖出观察：成本价±ATR止盈止损、MA5/MA10趋势转弱、买入日之后第3个交易日时间退出；录入买入日期后检查A股T+1限制。
- V1.3回测按同一套买卖规则模拟，固定100股、次日开盘在观察区间内才入场，含佣金、印花税和滑点假设。
- `data/screen.json` 是盘后研究结果；前端价格过滤基于全部已覆盖历史数据行，不是全市场完整覆盖。盘中买卖预警独立读取 quote-feed 快照。
- `quote-feed` 分支提供最近一次盘中行情快照；界面分别展示行情源时间与采集时间，过期判断以行情源时间为准，不把刚采集的旧报价误认为实时。
- 页面会明确显示行情日期和数据过期提醒，无真实数据时显示「未初始化」，**不会伪造任何实时价格或选股结果**。

## 启用 GitHub Pages
1. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
2. 打开 **Actions → AShare source tests and GitHub Pages → Run workflow**，并确认所有检查成功。
   - 也可以通过 `main` 分支的新提交触发部署；GitHub Pages 刚启用后，之前失败的工作流**不会自动变为成功**。
3. 网址：`https://gritechomepm-art.github.io/ashare-quant-personal/`，成功发布后才能访问。
4. 正常收盘依赖 **AShare BaoStock staged history bootstrap** 定时任务；`daily.yml` 为手动备用。未完成日 K 线时不可捏造结果。
5. **AShare best-effort intraday snapshots** 仅维护研究用快照，源数据可能延迟或被限流，不构成可执行的买卖预警。

## GitHub 工作流
- `.github/workflows/site.yml`：源码测试和静态网站部署。
- `.github/workflows/baostock-backfill.yml`：真实定时盘后更新（北京时间17:37/18:17尝试）并部署；`.github/workflows/daily.yml` 仅保留手动入口。
- `.github/workflows/quotes.yml`：交易日北京时间14:30计划通过独立 `quote-feed` 分支更新一次盘中公开行情；保留15:11盘后补采、BaoStock 工作流完成后的补充触发，以及手动入口。不每次上传 Pages Artifact；GitHub schedule 是尽力执行，不能保证准点。

## 已知限制
- 不保证行情为逐笔实时数据；腾讯公开快照可能延迟、缺失或限流，15分钟以外的盘中报价不生成预警。
- 历史数据覆盖仍是分批扩展；信号追踪只统计当前成功下载历史日线的股票，未覆盖股票不代表没有信号。
- 买卖信号是可解释的研究观察信号，不是自动委托或投资建议；策略参数尚需用完整历史样本做样本外验证。
- 策略历史回测未完整模拟停牌、涨跌停、历史退市股、分红除权及组合级资金占用；不可用于直接自动交易。
- 页面公开访问，持仓仅本机存储；建议定期导出本机记录，且不要把私有备份提交到仓库。


### 盘中行情更新诊断
- 盘中行情只发布到独立 `quote-feed` 分支，不触发 Pages 重建；网页每60秒重新读取该分支的快照。
- 行情工作流的 GitHub Actions 定时任务是 best-effort，不是实时调度器。运行详情中的 Step Summary 会记录触发方式、行情源时间、采集时间、覆盖率、新鲜报价比例及发布结果。
- 若页面时间不变，先检查 [quote workflow runs](https://github.com/gritechomepm-art/ashare-quant-personal/actions/workflows/quotes.yml) 是否有近期 `schedule` 运行，再检查 [quote-feed snapshot](https://github.com/gritechomepm-art/ashare-quant-personal/blob/quote-feed/data/quotes.json) 的 `quote_time_latest` 与 `fetched_at`。网页刷新本身不会生成新行情。
- 为避免连续触发时中途取消采集，行情任务不再取消正在运行的任务，并将单次执行上限调整为10分钟；行情源仍受腾讯接口可用性、延迟及限流影响。


## 盘中机会观察池（替代5,511只全市场采集）

- **盘后发现**：仍沿用现有 BaoStock 日线筛选与策略，不在盘中抓取5千多只股票。历史覆盖率必须如实显示；当前覆盖不完整时，候选池不能被视为完整A股机会排名。
- **盘中监测**：只读取 `data/screen.json` 已计算的股票，优先 `entry_signal=true`，其余仅纳入收盘价3–100元、评分≥55的高分观察候选；每次最多120只。不额外补齐随机股票或用全市场代码库兜底。
- **行情源校验**：按候选池规模核算成功比例（最低70%），盘中源时间在15分钟内的报价需至少60%；单只股票超过7分钟不得触发盘中预警。报价百分比是**候选池内采集时有效比例**，不是全市场覆盖率。
- **记录分离**：`quote-feed/data/quotes.json` 只保存候选池报价，`quote-feed/data/intraday_signal_events.json` 保留首次有效盘中信号记录。历史T+1模拟与盘中观察统计继续分开。
- **本机自选股**：用户的手机自选与持仓仍仅在浏览器本地，不上传服务器。未进入公共候选池的本机个股，不保证有盘中报价；这避免为个人私有持仓自动公开采集。
- **调度现实**：GitHub Actions cron 属于尽力执行的定时任务；14:30 是计划触发时间，不保证准点或必定执行。盘后补采和 BaoStock 完成后的补充触发仍保留。
